# ساعد — خدمات بلدك في إيدك

منصة مجانية بتوصّل أهل القرية اللي بيقدموا خدمات (تمريض، تحفيظ قرآن، دروس، كهربائي، سباك، توكتوك…) بالناس اللي محتاجاها. الزبون بيكلّم مقدم الخدمة على طول بالواتساب أو التليفون، والمنصة مش وسيط في الفلوس ولا في الحجز.

البداية من قرية **البجلات** (مركز منية النصر، الدقهلية)، والمنصة مبنية من الأول عشان تتوسع لأي قرية أو مدينة أو محافظة من غير ما يتغيّر سطر كود.

**التكلفة: صفر جنيه.**
- **الموقع:** على GitHub Pages.
- **قاعدة البيانات ودخول الأدمن:** على **Firebase بالخطة المجانية (Spark)**، من غير كارت فيزا.

## 1. قبل ما تبدأ

محتاج:

- **حساب Google** عشان Firebase: [console.firebase.google.com](https://console.firebase.google.com)
- **حساب GitHub** (مجاني): [github.com/signup](https://github.com/signup)
- **Node.js** نسخة 20 أو أحدث، لو عايز تشغّل الموقع على جهازك: [nodejs.org](https://nodejs.org)

> 💡 **الوضع التجريبي:** من غير أي إعدادات، الموقع بيشتغل ببيانات تجريبية (18 مقدم خدمة بأرقام وهمية). ده مفيد عشان تشوف الشكل قبل ما تربط Firebase. لما بيكون شغال كده، بيظهر شريط فوق مكتوب فيه «وضع تجريبي».

## 2. إعمل مشروع Firebase

### 2.1 المشروع

1. ادخل [console.firebase.google.com](https://console.firebase.google.com) واضغط **Create a project** (أو **Add project**).
2. اكتب اسم المشروع، مثلاً `saed`.
3. **Google Analytics:** اقفلها، مش محتاجينها.
4. اضغط **Create project** واستنى لحد ما يجهز.

> ⚠️ **متعملش Upgrade.** المشروع بيبدأ على خطة **Spark** المجانية، والموقع كله مبني عشان يشتغل عليها.

### 2.2 قاعدة البيانات (Firestore)

1. من القايمة الجانبية: **Build → Firestore Database → Create database**.
2. **Location:** اختار `europe-west1 (Belgium)` أو `me-central1 (Doha)`.
   > المكان ده مبيتغيّرش بعد كده.
3. اختار **Start in production mode** واضغط **Create**.
4. افتح تاب **Rules**، وامسح الكلام اللي فيه، والصق محتوى ملف [`firestore.rules`](firestore.rules) من المشروع، واضغط **Publish**.

> 🔒 القواعد دي هي اللي بتحمي الموقع:
> - الزوار بيقروا البيانات العامة بس.
> - الأدمن بس هو اللي بيكتب.
> - البلاغات والإحصائيات ليها شروط صارمة، فمحدش يقدر يكتب فيها أرقام أو كلام من عنده.

### 2.3 تسجيل الدخول (للأدمن بس)

1. **Build → Authentication → Get started**.
2. تاب **Sign-in method** ← **Email/Password** ← شغّل أول اختيار بس (**Email/Password**) ← **Save**.
3. **(مستحسن)** تاب **Settings** ← **User actions** ← اقفل **Enable create (sign-up)**. ده بيمنع أي حد يعمل حساب.
   > حتى لو حد عمل حساب، مش هيقدر يعدّل حاجة، لأن الكتابة مسموحة بس للأدمن. قفل التسجيل احتياط زيادة.
4. تاب **Settings** ← **Authorized domains** ← **Add domain** ← اكتب `USERNAME.github.io` (اسم حسابك على GitHub).

### 2.4 بيانات الربط

1. اضغط ⚙️ جنب **Project Overview** ← **Project settings**.
2. في **Your apps** اضغط على أيقونة الويب **`</>`**، واكتب اسم (مثلاً `saed-web`)، ومتعلّمش على Hosting، واضغط **Register app**.
3. هيظهرلك كود فيه `firebaseConfig`. انسخ منه **4 قيم**:

| في الكود | اسم المتغير عندنا |
|---|---|
| `apiKey` | `VITE_FIREBASE_API_KEY` |
| `authDomain` | `VITE_FIREBASE_AUTH_DOMAIN` |
| `projectId` | `VITE_FIREBASE_PROJECT_ID` |
| `appId` | `VITE_FIREBASE_APP_ID` |

> 🔒 القيم دي **عامة** وعادي تظهر في الموقع، لأن الأمان كله من قواعد `firestore.rules`.

## 3. إعمل حساب الأدمن

1. **Authentication → Users → Add user**، واكتب إيميلك وباسورد قوي، واضغط **Add user**.
2. هيظهر الحساب في الجدول. انسخ **User UID**، وده كود طويل زي `Xk3j…`.
3. افتح **Firestore Database → Data** ← **Start collection**:
   - **Collection ID:** `admins`
   - **Document ID:** الصق الـ **UID** اللي نسخته
   - ضيف حقل: **Field** = `email`، **Type** = string، **Value** = إيميلك
   - اضغط **Save**

خلاص، بقيت أدمن. عشان تضيف أدمن تاني، كرر الخطوات دي بحسابه.

## 4. شغّل الموقع على جهازك (اختياري)

```bash
npm install
```

انسخ ملف `.env.example` لملف جديد اسمه `.env.local`، وحط فيه القيم الأربعة اللي جبتها من خطوة 2.4:

```
VITE_FIREBASE_API_KEY=AIza...
VITE_FIREBASE_AUTH_DOMAIN=saed-xxxx.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=saed-xxxx
VITE_FIREBASE_APP_ID=1:123:web:abc
```

```bash
npm run dev
```

افتح `http://localhost:5173`.

| الأمر | بيعمل إيه |
|---|---|
| `npm run dev` | تشغيل للتجربة والتعديل |
| `npm run build` | بيبني الموقع في `dist/`، ويعمل صفحات SEO و `sitemap.xml`، وينسخ الصور |
| `npm run preview` | يعرض النسخة المبنية (فيها PWA) على `http://localhost:4173` |
| `npm run icons` | بيعمل أيقونات التطبيق وصورة المشاركة من جديد (افتح الرابط اللي هيظهر في المتصفح) |

## 5. ارفع الموقع على GitHub Pages

### 5.1 المستودع

1. على GitHub اعمل مستودع جديد: **New repository** ← اسمه مثلاً `saed` ← خليه **Public** (لازم يكون Public عشان GitHub Pages يبقى مجاني).
2. ارفع ملفات المشروع عليه. من مجلد المشروع:

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "أول نسخة من منصة ساعد"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/USERNAME/saed.git
```

```bash
git push -u origin main
```

> بدّل `USERNAME` باسم حسابك. ملف `.env.local` مش هيترفع لأنه موجود في `.gitignore`.

### 5.2 إعدادات GitHub

1. **شغّل GitHub Pages:** **Settings → Pages → Build and deployment → Source** ← اختار **GitHub Actions**.
2. **بيانات Firebase:** بيانات مشروع `saed-app-eg` مكتوبة جوه `.github/workflows/deploy.yml`، فمش محتاج تعمل حاجة. لو عملت مشروع Firebase تاني، ضيف بياناته في **Settings → Secrets and variables → Actions** ← تاب **Variables** ← **New repository variable**، وهي اللي هتتاخد بدل المكتوبة:

| الاسم | القيمة |
|---|---|
| `VITE_FIREBASE_API_KEY` | قيمة `apiKey` |
| `VITE_FIREBASE_AUTH_DOMAIN` | قيمة `authDomain` |
| `VITE_FIREBASE_PROJECT_ID` | قيمة `projectId` |
| `VITE_FIREBASE_APP_ID` | قيمة `appId` |

3. **انشر الموقع:** افتح تاب **Actions** ← اختار **Deploy** ← **Run workflow**. بعد دقيقتين تقريباً الموقع هيبقى على:

```
https://USERNAME.github.io/saed/
```

### 5.3 اللي بيحصل لوحده بعد كده

- **Deploy:** بيبني الموقع وينشره مع كل `git push`، و**كل 6 ساعات**. ده عشان حاجتين:
  - مقدمي الخدمة الجداد تتعملهم صفحات يلاقيها جوجل، ولينكاتهم تظهر بالصورة لما تتشارك على واتساب.
  - **صورهم تتنسخ من Firestore لملفات على GitHub Pages**، فالزوار ياخدوها من هناك ببلاش، من غير ما تستهلك من حصة Firebase.
- **على الموقع نفسه، أي حد تضيفه بيظهر فوراً** (وصورته بتيجي من Firestore لحد ما يحصل Deploy). لو مستعجل، شغّل **Deploy** بإيدك.

> 💡 **ليه الصور في Firestore ومش في Firebase Storage؟** لأن Firebase Storage بقى محتاج خطة **Blaze** (بكارت فيزا). عشان نفضل على الخطة المجانية:
> - الصورة بتتصغّر لحوالي 100KB وتتحفظ جوه Firestore.
> - مع كل Deploy بتتنسخ لملف على GitHub Pages.

> 💡 **دومين خاص (اختياري، بفلوس):** لو اشتريت دومين زي `saed-eg.com`:
> - ضيفه من **Settings → Pages → Custom domain**.
> - ضيف في Variables: `VITE_BASE` = `/` و `VITE_SITE_URL` = `https://saed-eg.com/`.
> - ضيفه كمان في Firebase: **Authentication → Settings → Authorized domains**.

## 6. أول دخول للوحة التحكم

1. افتح `https://USERNAME.github.io/saed/admin` (أو `http://localhost:5173/admin` على جهازك).
2. ادخل بالإيميل والباسورد بتوع خطوة 3.
3. أول مرة هتلاقي شاشة **«أهلاً بيك في ساعد»** لأن قاعدة البيانات لسه فاضية. اضغط **ابدأ**، وهيتحطوا:
   - الفئات الـ 15 وخدماتها.
   - الأماكن: الدقهلية ← مركز منية النصر ← البجلات ومنية النصر، ومعاهم المنصورة.
   - **اختياري:** 18 مقدم خدمة تجريبي، لو علّمت عليها.

> ⚠️ لو حطيت البيانات التجريبية، امسحها قبل ما تعلن عن الموقع. هتلاقي في صفحة مقدمي الخدمة رسالة فيها زرار **«امسح التجريبيين»**.

## 7. إزاي تضيف مقدم خدمة

### اللي بيحصل من ناحية مقدم الخدمة

1. بيدخل الموقع ويضغط **«سجّل اسمك»**، فيتفتحله واتساب على رقم الإدارة برسالة جاهزة فيها قالب البيانات.
2. بيملا البيانات ويبعتها، وبيبعت بعدها صورة شخصية.

### اللي بتعمله انت

1. **اتأكد منه على الواتساب:** كلّمه، واطلب يوريك البطاقة (مكالمة فيديو أو صورة). **صور البطايق والمستندات مش بتترفع على الموقع خالص**.
2. ادخل **`/admin`** واضغط **إضافة**.
3. **انسخ رسالته من الواتساب، والصقها** في الخانة الليموني اللي فوق، واضغط **«املا الفورم من الرسالة»**.
   - الاسم، والسن، والبلد، والخدمات، والأماكن، والمواعيد، والأرقام بيتملوا لوحدهم.
   - البرنامج بيفهم كلام زي «كل يوم ماعدا الجمعة» و«من 9 الصبح لـ 9 بالليل»، وبيفهم الأرقام العربي.
   - أي حاجة مفهمهاش بتظهرلك في **ملاحظة صفرا** عشان تكملها بإيدك.
4. **ارفع صورته.** الصورة بتتصغّر لوحدها في المتصفح لحوالي 100KB قبل ما تتحفظ.
5. **راجع البيانات:**
   - **الخدمة الأساسية:** أول خدمة (اللي عليها نجمة) هي اللي بتظهر على الكارت. اضغط ⭐ على أي خدمة تانية عشان تخليها هي الأساسية.
   - **«يظهر زرار الاتصال»:** لو مقدم الخدمة عايز التواصل بالواتساب بس، اقفلها.
   - **«خدمة نسائية»:** بتتعلّم لوحدها لما تختار «ست».
   - **«موثّق»:** علّم عليها بعد ما تتأكد منه.
   - **«مقدم خدمة مميز»:** بيظهر في أول النتائج (للمستقبل، لو حبيت تعملها خدمة مدفوعة).
6. اضغط **حفظ**، وصفحته هتظهر على الموقع **على طول**.

**التعديلات بعد الحفظ:**
- **إيقاف مؤقت:** اضغط ⏸ جنب اسمه في القايمة، وصفحته هتختفي من الموقع. بياناته بتفضل محفوظة، وترجّعه بزرار ▶.
- **مسح نهائي:** افتح **تعديل** واضغط **مسح** تحت.

## 8. إزاي تضيف قرية أو مدينة جديدة

الأماكن مرتبة كشجرة: **محافظة ← مركز ← (قرية أو مدينة)**.

1. ادخل **`/admin`** وافتح **الأماكن**.
2. اضغط **+** جنب المركز اللي القرية تبعه.
3. اكتب اسم القرية. الـ slug (اللي بيتكتب في الرابط بالإنجليزي) بيتعمل لوحده، وتقدر تعدّله، زي `mit-asem`.
4. اضغط **حفظ**. القرية بتظهر للزوار في «انت من أنهي بلد؟».

- **مركز جديد:** اضغط **+** جنب المحافظة.
- **محافظة جديدة:** اضغط **«+ محافظة»** فوق.
- **إخفاء مكان:** افتح **تعديل** واقفل «ظاهر في الموقع».

> الزوار بيحفظوا الفئات والأماكن على موبايلهم لمدة ساعة عشان الموقع يفتح أسرع. فالتعديل ممكن ياخد لحد ساعة على ما يظهر عند اللي كانوا فاتحين الموقع قبل كده.
> صفحات جوجل الخاصة بالمكان الجديد، زي «كهربائي في ميت عاصم»، بتتعمل مع أول Deploy.

## 9. الفئات والإعلانات والبلاغات والإحصائيات

كل ده موجود في لوحة الأدمن `/admin`.

### الفئات والخدمات

- تقدر تضيف أو تعدّل فئة، وتختارلها **لون** و**أيقونة**.
- تحت كل فئة، اضغط على خدمة عشان تعدّلها، أو **«+ خدمة»** عشان تضيف واحدة جديدة.
- **كلمات البحث** مهمة جداً. مثلاً لو كتبت للسباك «حنفية، مواسير، تسريب»، أي حد يدوّر بالكلمات دي هيلاقي السباك.

### الإعلانات

اضغط **«+ إعلان»** واملا:

- **مكان الظهور:**
  - بانر الرئيسية.
  - كارت بين نتائج الفئة (بيظهر بعد كل 6 مقدمي خدمة).
  - بانر في صفحة مقدم الخدمة.
- **صورة الإعلان:** مقاسها عرض 3 في طول 1، وبتتصغّر لوحدها.
- **رقم واتساب المعلن أو رابط:** لما حد يضغط على الإعلان، بيكلّم المعلن على طول.
- **تاريخ البداية والنهاية:** الإعلان بيختفي **لوحده** بعد تاريخ النهاية.
- **يظهر لمين:** «كل الأماكن»، أو تختار أماكن معينة. لو اخترت مركز، الإعلان بيظهر لكل قراه.

لما مفيش إعلان شغال في مكان، الموقع بيعرض مكانه إعلان داخلي «سجّل اسمك» أو «أعلن معانا».

### البلاغات

- أي زائر يقدر يبلّغ عن مشكلة من صفحة مقدم الخدمة، والبلاغ بيوصلك هنا.
- لكل بلاغ تقدر تعلّمه **اتراجع** أو **تجاهل**، أو تكلّم اللي بلّغ لو ساب رقمه، أو **توقف مقدم الخدمة** على طول.
- لو مقدم خدمة عليه أكتر من بلاغ، بيظهر جنبه عددهم.

### الإحصائيات

- **الأرقام:** زيارات الموقع، وضغطات الواتساب والاتصال، والمشاركات، وضغطات الإعلانات. تقدر تشوفها لآخر أسبوع أو شهر أو 3 شهور.
- **الجداول:**
  - أكتر مقدمي الخدمة اتطلبوا.
  - **الزوار حسب البلد**: دي الأرقام اللي بتوريها للمحلات عشان تبيعلهم إعلانات.
  - الفئات.
  - الإعلانات.
- زرار **«تقرير للمعلن»** بينسخ ملخص جاهز تبعته على الواتساب.

> الإحصائيات مش بتحفظ أي بيانات شخصية عن الزوار، دي مجرد عدّادات يومية.
> «الزيارة» بتتحسب مرة واحدة لكل زائر في الجلسة، عشان الأرقام تبقى حقيقية وكمان نوفّر من حصة Firebase.

## 10. تعديلات شائعة

| عايز تغيّر | فين |
|---|---|
| رقم واتساب الإدارة | `src/config.js` ← `adminWhatsapp` (بالصيغة الدولية من غير +، زي `201008137502`) |

بعد أي تعديل في الكود، اعمل `git push` والموقع هيتحدّث لوحده خلال دقيقتين.

| الموقع لسه بيقول «وضع تجريبي» بعد الرفع | اتأكد إن متغيرات `VITE_FIREBASE_…` الأربعة متضافة في **Variables** (مش Secrets)، وبعدين شغّل **Deploy** تاني |
| صفحة بيضا بعد الرفع | اتأكد إن **Pages → Source** = GitHub Actions، وإن آخر Deploy في تاب Actions نجح (علامة ✓ خضرا) |
| «الإيميل أو الباسورد غلط» | اتأكد إن **Email/Password** متفعّل في Authentication، وإن الحساب موجود في **Users** |
| «الحساب ده مش أدمن» | اتأكد إن فيه مستند في مجموعة `admins` واسمه **نفس الـ UID بالظبط** |
| «Missing or insufficient permissions» | قواعد `firestore.rules` مش متنشرة. الصقها في **Firestore → Rules** واضغط **Publish** |
| مقدم الخدمة مش ظاهر | اتأكد إن حالته **نشط**، وإن عنده خدمة واحدة على الأقل، وإن البلد اللي الزائر مختارها من ضمن «ساكن في» أو «بيغطي» |
| لينك صفحة مقدم الخدمة بيظهر من غير صورة على واتساب | لسه متعملهوش Deploy. استنى لحد 6 ساعات أو شغّل Deploy بإيدك. واتساب ممكن كمان يكون حافظ النسخة القديمة لفترة |
| ظهرت رسالة إن الحصة اليومية خلصت (Quota exceeded) | الحصة بتتجدد كل يوم. لو بتتكرر كتير، يبقى الموقع كبر، وساعتها اقرا الجزء اللي جاي |

## 12. حدود الخطة المجانية

**خطة Spark من Firebase:**

| الحاجة | الحد المجاني | يعني إيه للموقع |
|---|---|---|
| قراءات Firestore | 50,000 في اليوم | الزائر بيستهلك حوالي 3–5 قراءات بس، فده يكفي **آلاف الزوار يومياً** |
| كتابات Firestore | 20,000 في اليوم | كل زيارة حوالي 2 كتابة (للإحصائيات)، وكل ضغطة واتساب حوالي 3–4 |
| مساحة Firestore | 1GB | حوالي 7000 صورة (كل صورة حوالي 100KB)، والباقي بيانات صغيرة |
| دخول الأدمن (Authentication) | مجاني | — |

**GitHub:**

| الحاجة | الحد المجاني |
|---|---|
| GitHub Pages | 100GB في الشهر، والصور بتتخدم من هنا |
| GitHub Actions | مفتوح للمستودعات الـ Public |

**ليه الموقع خفيف على الحصة؟**
- كروت مقدمي الخدمة لكل محافظة متجمعة في **مستند واحد**، فالزائر بيقرا مستند واحد بس.
- الإعلانات كلها في **مستند واحد**.
- البحث والفلترة بيحصلوا **في الموبايل نفسه**، من غير ما يكلّموا Firebase.
- الصور بتتخدم من **GitHub Pages**، مش من Firebase.
- الفئات والأماكن بتتحفظ على موبايل الزائر لمدة ساعة.

> لو المنصة كبرت جداً وقربت من الحدود، تقدر تحوّل لخطة **Blaze**. بتديك نفس الحصة المجانية، وبتدفع بس على اللي يزيد عنها، وده غالباً سنتات. بس محتاجة كارت فيزا.

## 13. هيكل المشروع

```
├─ .github/workflows/deploy.yml  ← بناء ونشر على GitHub Pages (مع كل push وكل 6 ساعات)
├─ firestore.rules               ← قواعد الأمان (الصقها في Firebase Console)
├─ scripts/
│  ├─ prerender.mjs              ← صفحات SEO والمشاركة + sitemap.xml + نسخ الصور من Firestore
│  └─ make-icons.mjs             ← أيقونات التطبيق وصورة المشاركة
├─ pwa/sw.js                     ← Service Worker (الموقع يفتح بسرعة على النت الضعيف)
├─ public/                       ← الأيقونات، و manifest، وصورة المشاركة
└─ src/
   ├─ config.js                  ← الإعدادات العامة (الاسم، رقم الواتساب، Firebase)
   ├─ data/seed.js               ← الفئات والأماكن والبيانات التجريبية
   ├─ lib/
   │  ├─ firebase.js             ← الاتصال بـ Firebase + شكل البيانات في Firestore
   │  ├─ api.js                  ← كل طلبات الزوار
   │  ├─ search.js               ← البحث والفلترة (بيشتغل في الموبايل)
   │  ├─ photos.js               ← الصور (GitHub Pages الأول، وبعدين Firestore)
   │  └─ …                       ← البحث العربي، والواتساب، والمواعيد، وضغط الصور، وقراءة رسالة الواتساب
   ├─ components/                ← الكروت، والإعلانات، واللوجو، واختيار البلد
   ├─ pages/                     ← صفحات الزوار
   ├─ admin/                     ← لوحة الأدمن (بتتحمّل لوحدها، والزائر العادي مش بينزّلها)
   └─ styles/app.css             ← التصميم والألوان (فاتح وغامق)
```

### شكل البيانات في Firestore

| المجموعة | فيها إيه | مين يقرا |
|---|---|---|
| `catalog/main` | الفئات والخدمات والأماكن | الكل |
| `public_index/{رقم المحافظة}` | كروت مقدمي الخدمة المعتمدين في المحافظة | الكل |
| `public_providers/{id}` | صفحة مقدم الخدمة (فيها النبذة) | الكل |
| `public/ads` | الإعلانات | الكل |
| `photos/{id}` | الصور المضغوطة | الكل |
| `providers/{id}` | البيانات الكاملة، وفيها السن والملاحظات ورسالة الواتساب | الأدمن بس |
| `ads/{id}` | تفاصيل الإعلانات | الأدمن بس |
| `reports/{id}` | البلاغات (الزائر يضيف بس) | الأدمن بس |
| `counters/{يوم__نوع__id}` | عدّادات الإحصائيات | الأدمن بس |
| `admins/{uid}` | حسابات الأدمن | — |
